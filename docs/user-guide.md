# User guide

A Next.js + TypeScript implementation of the supplied Resume Builder handoff. The app starts empty and works with your imported resumes, saved jobs, and notes.

## Run locally

Requires Node.js 22.18 or newer. Persistence uses the built-in `node:sqlite` module, which is still marked experimental on Node 22; the database format is standard SQLite.

```sh
npm install
npm run dev
```

Open http://localhost:3000, or use `npm run dev -- --port 3001` when port 3000 is occupied. For a production build, run `npm run build` followed by `npm start`.

```sh
npm run typecheck
npm test
npm run build
```

## Implemented

- Job cards show the company and an inline application status, such as **Company • To apply**. New jobs have no status label. Use the dropdown beside the company to manually choose **To apply**, **Applied**, or **Rejected**, or choose **No status** to clear the label; the choice saves on this device.
- Collapse individual job cards with their chevron to show only the company and title, or use **Collapse all** above the list to fit more jobs. **Expand all** restores the details. Collapsed cards can still be selected and reordered; their visibility is remembered in this browser.
- Search above the job list by company, title, location or keyword; search ignores case and accents. Combine **Status** and **Resume** filters, see the matching job count, or use **Clear filters** to restore the full list. Collapse/expand all affects the displayed results; reordering filtered jobs keeps hidden jobs in place.

- Three independently scrolling panels, collapsible rails, responsive layout, and the handoff typography/colors.
- Resize the Templates/Jobs and AI Match side panels by dragging their shared edge with the resume editor. Widths save on this device and survive reload/collapse. Handles support arrow keys (Shift for larger steps), Home/End and double-click to reset. Limits preserve at least 320px for the center editor on desktop; narrower windows shrink side panels automatically. Mobile retains overlay panels.
- Reorder resume sections using the drag handle or **↑ / ↓** beside each heading (buttons work on mobile and with the keyboard). Standard sections and imported additional sections can move together; the name/contact header stays at the top. Order saves per resume, follows duplicates/tailored copies, participates in undo/redo, and is used by PDF preview/download and recognized section headings on import.
- Experience groups adjacent roles by company and optional team, preserving chronology. Use **+ Add company**, **+ Add team**, **+ Add role**, or **+ Add role in team**; **Set team / Change team** assigns individual roles. Shared headings rename the whole group. Team names persist in saved resumes, copies, AI context, and PDF exports. PDF exports show company/team names without prefixes and align dates to the right margin; semantic heading tags preserve experience grouping on re-import. Explicit Company/Team (or Entreprise/Équipe) headings in other documents are still recognized on import. Existing resumes keep working without teams.
- **Undo / Redo keyboard shortcuts** support resume text, company/team/role changes, bullets, education, page count, accepted AI edits, tailored-copy creation and discarding tailoring. A field editing session is one step, with up to 100 steps in memory. Use Cmd/Ctrl+Z to undo and Cmd/Ctrl+Shift+Z or Cmd/Ctrl+Y to redo, including while editing resume text. Resume fields share the app's history, so redo still works after focus moves. Other text inputs retain native undo. Undo returns to the edited resume and leaves notes/jobs intact. New edits clear redo. Reloading, importing/duplicating/deleting templates, changing a job's base template or clearing the workspace starts a new history; imports and template deletions are not undoable.
- Editable resume fields, roles, education, and bullets; AI-only resume/job assessments with quoted evidence, explanations and focused highlights; a single match-percentage view.
- Open **Debug matching** in the right panel to inspect the last request. Click **Reassess with AI** in the matching panel to capture a new request. Inspect the live client/server stage timeline, request ID, HTTP/provider status, CLI exit code, batch counts and response/evidence validation errors. **Copy debug report** or **Download report** exports a redacted JSON report without credentials, resume/job text or raw AI responses. Reports stay in memory and are reset on reload.
- Clicking a matched skill scrolls to and highlights its supporting text in the resume, including semantically equivalent evidence. **+ Skills** scrolls to the Skills field and selects the added text for editing. Already-listed skills are focused without duplication. On mobile the match overlay closes to reveal the focused resume. These actions do not trigger AI reassessment.
- The matching panel shows the AI match percentage and a compact key-skill list grouped into **Matched** and **Missing**. The list includes language, technology and behavioral skills; AI determines their matched/missing status. Expand a skill for its reason, verified evidence, required/preferred label and optional Add to Skills action. Overall reasoning, improvement tools and debugging stay collapsed until needed.
- Matching runs once after a job is added, using its selected resume and the saved Claude/Codex connection. The result and its assessment date are saved with the job in the local SQLite database. Reloading, switching jobs/templates, changing AI settings or editing a resume never triggers another matching request. **Reassess with AI** is the only way to rerun matching afterward; it replaces the saved result on success. A notice marks changed resume/job inputs, while keeping the previous result visible. Failed or canceled reassessments keep the last successful result. Job scanning still extracts posting details/skills before saving; it does not assess resumes during the review step. Older jobs without a saved assessment wait for manual reassessment.

- Shared templates, deletion from the resume toolbar or template list with linked-job reassignment (jobs, tailored copies, and notes remain saved), duplication, template reassignment, isolated tailored copies, discard tailoring, and automatic tailoring for job-specific skill additions and accepted AI suggestions.
- Notes accepts **Import reference** uploads of PDF, DOCX and TXT documents, up to 10 MB and 150,000 extracted characters each (30 references). They remain separate from resume templates. Original files and full extracted text are stored in browser IndexedDB; metadata saves with the workspace. Open a reference to view its PDF/text or download the original; remove it from Notes when no longer needed. AI chat and notes-based suggestions receive the named reference text as untrusted context, without treating every project/company statement as the user's own achievement. Importing references does not trigger matching. Workspace reset clears references and their stored files. Image-only PDFs require OCR before import.
- Private notes, editable job previews, keyword review, and automatic base-template recommendations.
- Real DOCX/PDF text extraction, drag-and-drop upload and downloadable PDF export. New PDF imports retain the original file and extracted text in browser IndexedDB for exact preview/download and comparison with the editable version. Deleting a template or clearing the workspace removes its saved original file. Older imports need reimporting to save their source PDF. An always-visible Pages dropdown in the top bar selects Single page or Dual page; PDF preview and downloads use exactly that page count. Layouts adjust font sizes within a readable range; oversized content reports an error instead of being clipped. The choice autosaves per resume and follows duplicates and tailored copies. Choosing it before importing sets the default for new resumes. Without a selected default, PDF imports use their detected page count, capped at two.
- AI-scanned company job imports using JobPosting JSON-LD or encoded Zoho Recruit posting data when available, plus pasted descriptions. Incomplete metadata falls back to visible page content; unreadable or blocked links switch to the paste form with a specific explanation. The connected Claude or Codex/OpenAI provider extracts job details and categorizes required versus preferred skills; you review the results before saving. An AI connection is required, and failed scans can be retried. LinkedIn restrictions and failed fetches lead to the paste fallback. URL fetches validate public addresses, pin DNS, restrict redirects, and cap response sizes.
- Claude and Codex/OpenAI connections with API-key and local subscription modes. The last successfully connected provider, method, model and API key (when used) are saved in this browser on this device and restored automatically; subscription mode reuses the official CLI sign-in without extracting tokens. Suggestions use actual provider requests, are grounded in your resume/notes, and require review before acceptance.
- AI chatbot using the same Claude/Codex API or subscription connection. Open **AI chatbot** in the top bar or the **AI chat** tab in the right tools panel to ask questions, improve wording, or prepare for interviews. Chat is docked beside the resume and shares the resizable right panel with **Resume match**. Switching tabs or collapsing the panel preserves the current conversation and draft. Use the arrow keys, Home or End on the tabs to switch tools. On mobile, the tools open in the existing right-side drawer. Each request includes every saved template and resume document (including tailored versions and extra sections), all job descriptions/keywords, all notes, available original PDF text, and the recent conversation. The current selection is identified so you can refer to “this resume” or “this job”, while asking about any other saved item. Use **Instructions** in the chat header to save a custom system prompt for language, tone, task, and preferences. Instructions are applied in the provider system prompt for both API and subscription modes, persist on this device, and can be reset to defaults. Replies can be copied. Ask the chatbot to improve, rewrite, or tailor resume text to get proposed edits with a red/green before-and-after preview and Apply change / Dismiss controls. Applying a job-chat change creates or updates that job’s tailored resume; template-chat changes update the selected base template. Changes are explicit, support undo/redo, and cannot overwrite a field that changed after the suggestion was generated. Suggestions and dismissal status are saved with the chat. Each job has its own conversation saved in the local database. Switching jobs restores that job’s chat; viewing a resume template uses a separate workspace conversation. Saved history survives refreshes and AI connection changes. New chat clears only the current conversation; clearing the workspace removes all saved chats. The full conversation stays visible while only recent messages are sent to the provider. Replies render Markdown and sanitized basic HTML, including lists, tables, and code blocks.
- Workspace data autosaves in a local SQLite database on the computer running the server. Ports and browsers share the same workspace when the server uses the same data directory. New workspaces contain no sample records. Previously seeded demo records are removed automatically while user imports, real jobs and user-added notes are retained. Use **Templates → + New** to create an empty resume directly, or **Start blank** in the import dialog. Each empty resume is a separate template with a unique untitled name and your selected page layout. Click the duplicate icon beside any template, or **Duplicate** above the selected template, to create an independent copy with a unique name, the same page layout, and its saved original PDF when available. Use the pencil icon beside a template to rename its label; resume content, original files, and job links stay intact. Blank resumes contain empty editable fields, not prewritten resume content. Use Import resume → Start fresh to clear your workspace, with confirmation.

## AI connections

Choose **Connect AI → Claude or Codex → API key or Subscription**.

- **API key:** enter an Anthropic or OpenAI Platform API key and a model ID. Usage is billed to that API account. Requests use the official `@anthropic-ai/sdk` and `openai` SDKs. OpenAI API mode uses OpenAI text models through the API; subscription mode runs Codex.
- **Subscription:** install the official [Codex CLI](https://developers.openai.com/codex/cli) or [Claude Code CLI](https://code.claude.com/docs/en/quickstart) on the computer running the app. Sign in with `codex login` (ChatGPT) or `claude auth login` (Claude subscription), then click **Connect subscription**. Leave Model empty to use the CLI default. The app checks the authentication method and rejects API-key CLI sign-ins in subscription mode.

The server searches its PATH for the CLI executable. On macOS and Linux it also checks `~/.local/bin`, `/opt/homebrew/bin`, and `/usr/local/bin`, so native and Homebrew installations work when starting the app from a desktop launcher. Subscription mode is available by default for local development. For a local production build, set `ENABLE_LOCAL_AI_SUBSCRIPTIONS=true` in `.env.local` before starting the server. Keep it disabled on hosted/shared servers. Development and production scripts bind to `127.0.0.1`; subscription endpoints require localhost and same-origin requests.

Claude subscription requests run through the [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk) (`@anthropic-ai/claude-agent-sdk`) using your `claude auth login` sign-in; the `claude` CLI is still used to verify that sign-in. Codex subscription requests run the `codex` CLI.

The app uses temporary isolated directories, bounded child processes, disables Claude tools/MCP/hooks and Codex shell/browser/plugin features, and runs Codex in a read-only sandbox. It deletes temporary prompts/results after each run and does not save CLI sessions. Inherited API keys and OAuth token environment variables are excluded so subscription mode cannot silently fall back to API billing. Disconnect affects this app, not your shared CLI login. Reloading restores the saved connection automatically for matching, chat, job scans and tailoring. Disconnect removes this app’s saved settings, including a saved API key, while leaving CLI sign-in available.

Subscription use is subject to your provider’s plan, available models and usage limits. See [Codex authentication](https://developers.openai.com/codex/auth) and [Claude Agent SDK subscription guidance](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan).

## Google Drive

Copy `.env.example` to `.env.local` and set `NEXT_PUBLIC_GOOGLE_CLIENT_ID` to a Google OAuth **web** client ID. Enable Google Drive API, configure the consent screen (add test users while in testing), and allow `http://localhost:3000` as an authorized JavaScript origin. Restart the app after changing the environment. The app requests read-only Drive access and lists PDFs, Word documents, and Google Docs. Google Docs are exported to DOCX for parsing. Tokens remain in memory.

## Scope and limitations

This is a working single-user local app. It does not include authentication, a hosted database, cloud synchronization, billing, or a deployed service. Workspace data is stored on the server computer; clearing browser storage does not remove it. API connection credentials and panel widths remain browser preferences and are specific to the browser address. Reconnect AI when changing ports or browsers. SQLite does not provide cloud synchronization; transfer a complete backup to move to another computer. API connections require your own provider account and credit; model IDs are editable to suit your account. New job postings are sent to the connected AI provider when you scan them. Resume content and the job description are sent automatically for matching while AI is connected; template comparison assesses each relevant template or job. Notes are included when requesting AI editing or sending a chatbot message.

The deterministic document parser preserves extracted text and detects common section headings. It does not infer employers and dates reliably from arbitrary layouts; English and French headings are detected, and projects, certifications, languages, and other supported additional sections remain editable and are exported/scored; common role headers and date ranges are detected; unfamiliar experience layouts are grouped for review and inline correction. Scanned image-only PDFs require OCR elsewhere. Job keyword extraction uses the chosen AI provider and supports reviewing, removing, and adding terms. PDF export uses embedded standard PDF fonts and a clean resume layout; unsupported scripts need a Unicode font integration for export. Cloud services can be added behind the existing API routes.

## Local data and recovery

On macOS the database is stored at `~/Library/Application Support/ResumeBuilder/resume-builder.sqlite`. On other systems it uses `$XDG_DATA_HOME/ResumeBuilder`, or `~/.local/share/ResumeBuilder` if that variable is unset. To choose a directory, set `RESUME_BUILDER_DATA_DIR` to an **absolute path** in `.env.local` and restart the server. Use the same directory for every port and checkout. Data is never placed in `.next` or the repository by default. Directory/file permissions restrict the data to the local account; the database is not encrypted.

The database stores the workspace, job/workspace chats, custom chat instructions, page preference, and original PDF/DOCX/reference file bytes. Resume edit/undo history stays in memory. Autosave waits 450 ms after an edit, serializes writes and checks a workspace revision. The UI shows **Saving…**, **Saved on this computer**, or **Save failed**. A failed initial load blocks editing and never saves an empty workspace. A stale tab is rejected instead of silently overwriting newer work; use **Download unsaved work**, reload, then **Backup & recovery → Import backup** to recover that draft if needed. Draft recovery can replace newer edits, so review it first; the current database is backed up before replacement.

When an uninitialized database is opened from an address with an old browser workspace, the app imports that workspace, chats, instructions and available IndexedDB files once. The old browser data is never cleared or updated by the migration. If a database already exists, use **Backup & recovery → Import browser workspace** to review and explicitly import the browser copy. This replaces the database workspace and first creates a recovery snapshot; it does not merge separate workspaces.

To recover data from port 3000 while working on port 3001:

1. Use the same browser and exact original hostname (for example `localhost`, not `127.0.0.1`).
2. Open `http://localhost:3000/recovery.html` with this project serving that address. The standalone page reads old browser storage without accessing the database. Download a browser backup. If another app owns port 3000, open `/recovery.html` on the current Resume Builder port and follow its **Recover browser resumes** bookmark instructions. The bookmark runs the read-only recovery tool at the old origin without stopping that app. If its content security policy blocks the tool, serve this project's recovery page at the original address instead.
3. Open the current app and choose **Backup & recovery → Import backup**. Review the counts before choosing **Import workspace**. Existing saved data gets a recovery snapshot first; the browser copy remains intact.

The standalone page also offers a raw recovery download if legacy JSON needs repair. Raw exports exclude saved AI credentials and are for manual recovery, not direct import. Missing original files do not discard editable resumes. Older DOCX imports may need re-uploading to retain their original bytes, because the old app only stored original PDFs.

**Backup & recovery** can download a complete JSON backup, save a manual SQLite snapshot, or restore a saved snapshot. A daily snapshot is created on the first write when you use the app; the latest 14 daily snapshots are retained. Manual snapshots and snapshots made before import/clear are retained until you remove them yourself. Snapshots use SQLite's consistent online backup API. Do not copy only a live `.sqlite` file as a backup: recent writes may be in its WAL sidecar. Backups remain on the same computer; download one to keep elsewhere for protection against disk loss. Ordinary workspace exports exclude API keys, and API keys remain in the original browser's connection settings.

Database routes require a loopback host and same-origin writes. This remains a local single-user app, without remote authentication. To host it elsewhere, add authentication and durable storage rather than exposing these local routes.

## Verification

Run `npm run typecheck`, `npm test`, and `npm run build`. After building, run `npm run test:storage:browser` for the current end-to-end storage checks. This starts temporary production servers on two free ports with a temporary data directory and fresh browser contexts, so it never touches your workspace. It verifies legacy browser/IndexedDB migration, preserved browser copies, original file bytes, chats/instructions, separate ports/hostnames/browser contexts, stale tabs, save failure/retry, backup/import/reset, failed initial loads, server restart, and mobile layout. Screenshots and fixture backups are written to `test-results/storage/`.

On macOS browser checks use installed Google Chrome; elsewhere install Playwright Chromium with `npx playwright install chromium`, or set `BROWSER_EXECUTABLE_PATH`. The older feature browser scripts still use browser-local storage fixtures and need adaptation before they can target SQLite; do not run them against your personal database.
